# Панель модерации — Telegram Mini App + бот

Панель для учёта смен модераторов и выплат за модерацию в TON:
Telegram Mini App (одна страница), бот на aiogram 3, REST API на aiohttp, SQLite.

## Состав

| Путь | Назначение |
|---|---|
| `webapp/index.html` | мини-приложение (все экраны, темы, админ-панель) |
| `main.py` | запуск бота (polling/webhook) и API |
| `app/bot.py` | капча, команды, решения по заявкам |
| `app/api.py` | REST API для мини-приложения |
| `app/db.py` | схема и запросы SQLite |
| `app/security.py` | проверка HMAC-подписи `initData` |
| `app/payments.py` | формирование ссылки на перевод TON |

## Экраны

* **Главная** — баланс, профит, место, стрик; витрина закрытых задач; регламент; приглашение коллег.
* **Профит** — пошаговая заявка на выплату (тег смены → отчёт → скриншот → кошелёк → подтверждение),
  статистика за период и история заявок.
* **Топ** — подиум топ-3 и остальные участники, фильтры «Всё время / Месяц / Неделя / День».
* **Ещё** — розыгрыши, менторы, промокод, рейтинг, дуэли, достижения, зал славы, командный чат,
  мои задачи, рефералы, обои, настройки, админ-панель.
* **Профиль** — уровень и лимит, график выплат за 30 дней, кошелёк, статус заявки, настройки, 10 тем.

## Запуск локально

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env   # заполнить BOT_TOKEN, ADMIN_IDS, ADMIN_PANEL_PASSWORD
python main.py
```

Мини-приложение — статический файл. Для локальной проверки:

```bash
python -m http.server 5500 --directory webapp
```

Затем в консоли браузера указать адрес API:
`localStorage.setItem('api_base', 'http://localhost:8080')`.
Без API страница работает в демо-режиме на `localStorage`.

## Деплой

**Мини-приложение — GitHub Pages:** включить Pages для ветки с каталогом `webapp/`
(или скопировать `webapp/index.html` в корень ветки `gh-pages`), затем указать полученный
URL в `WEBAPP_URL` и в BotFather → *Bot Settings → Menu Button*.

**Бот и API — Render (Web Service):**

* Build: `pip install -r requirements.txt`
* Start: `python main.py`
* Переменные окружения: см. `.env.example`. Для webhook задать `WEBHOOK_HOST`
  (`https://<service>.onrender.com`) и `WEBHOOK_SECRET`; без `WEBHOOK_HOST` бот работает на polling.
* `CORS_ORIGIN` — origin GitHub Pages, чтобы браузер разрешил запросы к API.

## Как проходит выплата

1. Модератор заполняет заявку в мини-приложении → `POST /api/payout`.
2. API проверяет подпись `initData` и отправляет заявку админам в бот
   (кнопки «Принять» / «Отклонить») и в админ-панель приложения.
3. При принятии админ вводит сумму: статус → `accepted`, баланс модератора увеличивается,
   пользователю и в группу уходят уведомления.
4. Сервер возвращает ссылку на перевод (`app.tonkeeper.com/transfer/…`), которую
   администратор подписывает в своём кошельке.

**Почему нет автоотправки с сид-фразой.** Приватный ключ на публично доступном веб-сервисе
означает, что любая уязвимость API = потеря всех средств кошелька, поэтому перевод
подписывает владелец средств. Если нужна автоматизация, безопасный путь —
отдельный подписывающий сервис в закрытой сети с лимитами на сумму и вайтлистом адресов.

## Безопасность

* Все запросы API авторизуются через HMAC-подпись `initData` (секрет — токен бота).
* Вход в админ-панель: Telegram-ID в `ADMIN_IDS` **и** пароль из `ADMIN_PANEL_PASSWORD`
  (в коде пароля нет; токен сессии живёт в памяти процесса).
* Токен бота, пароль и адрес кошелька задаются только через переменные окружения.
* Скриншоты не сохраняются на диск: файл пересылается админу в Telegram.

## Команды бота

| Команда | Кто | Действие |
|---|---|---|
| `/start` | все | капча (один раз) и кнопка «Перейти в приложение» |
| `/admin` | админы | список заявок с инлайн-кнопками |
| `/ban`, `/unban`, `/broadcast` | админы | модерация и рассылка |
| `/topm`, `/topn`, `/stat` | все | топ за месяц / неделю, общая статистика |
